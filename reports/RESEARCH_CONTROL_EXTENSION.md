# 范围更正与研究控制元程序扩展

用户指出的两项限制成立。`3ccda3f` 中的 MetaPolicy 主要改变评分与排序，发明/世界产物来自有界表达式
语言；这不能等同于开放式研究工作流重构，更不能等同于任意复杂算法的自主发明。
此前无条件的“M2–M7 全部完成 / CODE-COMPLETE”说法过宽，本次予以更正。

## 这次实际增加的能力

`research-control-v1` 是独立的、可执行的结构化数据控制语言：

- 自定义函数和函数调用、词法变量、条件分支、有限集合 fold、受 fuel/深度限制的递归；
- JSON 对象/列表构造、字段投影、整数/布尔运算，可以编写新诊断子程序和代码构造过程；
- `evaluate` 查看指定 TRAIN 证据上的候选误差，`predict` 执行模型预测；
- `invent` / `experiment` 调用已有研究原语，`emit` 提交工作流自行构造的程序或动作协议；
- `model` 可调用实际配置的模型客户端，再根据返回结果决定后续操作；缺少客户端时明确拒绝。

因此，元程序现在可以改变 **执行哪些研究步骤、如何处理证据、怎样构造和筛选实验程序、
是否以及何时调用模型**，不只改变候选最终顺序。它可以在上一操作的反馈上继续计算。

默认初始工作流是明确标注的兼容策略，不作为“发明成果”。本地元搜索对实际控制 AST 做子树变异、
交叉移植和依公开记录 schema 组合诊断谓词，先在 train 机会上实际执行，只有产生不同研究产物的
候选才被提出；评分公式变化不是必要条件。模型客户端也能直接提交完整函数/入口源码。
候选仍须通过原有独立元 Gate；执行轨迹不同或源码变复杂不能单独建立元能力提升。

## 接线、证据与安全

- `core/control.py`：控制产物、初始策略、结构变异；`core/meta.score` 兼容独立评分部分。
- `runtime/control.py`：静态结构/作用域校验及有界解释器。
- `runtime/control_research.py`：只封装 train/public 数据的窄能力接口，实际产生 Snapshot/ResearchArtifact。
- `runtime/sandbox.py`：spawn worker 通过有界 JSON 请求能力；另一个工具 worker 执行候选表达式，
  避免对暂停的控制 worker 重入。模型凭据、Adapter 对象和私有评测数据不进入控制 worker。
- `SynthesisRuntime.candidates/adapt`：实际运行工作流；固定父任务/对手/机会，旧排序策略和新工作流
  使用相同预登记搜索与预测上限，因果适应最多一次模型调用。Token 继续由真实客户端预留。
- `ModelResearchRuntime`：解析完整工作流、执行继承工作流，真实模型 effect 仍保留原始调用与训练连接。
  没有新的模型采样记录时明确跳过神经训练，不把纯程序搜索声称为权重训练。

原有 Gate、Archive、BoundaryCertificate、世界参考语义及 24 项锁定规范均未修改。
工作流的诊断不能改写“空间被证伪”的证书。动态错误、能力拒绝、fuel/预算超限使本次适应失败；
失败前暂存的产物丢弃，不能部分继承。源码、能力调用、结果、训练证据哈希、资源分配和错误留档。
无 diagnosis 对照不向工作流暴露 refutation 字段；Reflection 保持原先明确限定的基线定义。

## 测试含义

`tests/test_research_control.py` 包含实际行为与失败测试：

1. 评分函数相同，替换诊断函数后实际工具调用数和分支不同。
2. 读取预测结果后构造并提交实验，不依赖最终候选重排。
3. 在控制语言中构造表达式源码，绕开固定发明算子菜单；提交仍经类型和 train 行为检查。
4. 真实 Adapter 执行工作流生成的协议；dev 证据不能进入工作流。
5. 后续操作非法时丢弃先前暂存产物。
6. 模型能力的协议 fixture 贯通；不能通过循环购买额外模型调用。
7. 非法能力、作用域错误、递归/fuel、超大请求被拒绝，错误后 IPC 不失步。
8. 结构变异实际修改流程源码，保持评分表达式不变。

其中手写程序和模型 fixture **只验证语言/接口行为**，不冒充 Agent 自主发明的科学成果。
本次实际执行：**90/90 完整测试通过（51.678s）**，其中新增 11 项控制语言行为/失败测试。
新的两域一代闭环均通过 Replay：stateful-scm 109 episodes / 135 records，string-transducer
72 episodes / 99 records。实际提出的元候选中，两个领域分别有 2/3 与 3/3 个控制语言产物；
分别记录 10 次和 11 次控制工作流执行（不是成功率）。两域的所有独立元 Gate
均为 INCONCLUSIVE，没有为了宣称“工作流进化成功”强制接受。
完整回归和新的双域演示记录见 `evidence/control-extension/`。

## 尚未解决的部分

- **第二项限制仍然存在。** 世界和假设产物主要仍是原有表达式语言；没有实现任意复杂程序、
  任意新领域机制或任意外部科学方法的开放式自主发明。新增控制语言也有固定语义、能力和资源边界。
- 当前重构主要作用于 **离线 train 适应与实验程序生成**，不是任意在线 Domain Session 的逐步控制器。
- 本地结构变异是有限搜索；支持编写新子程序，不等于已证明能自主发现有用的新诊断算法。
- 新增控制能力尚未经历真实 LLM、LoRA/RL 或外部 benchmark 实验。现有真实客户端连接没有被 fixture 替代。
- 没有证明工作流元进化提高了发明效率，也没有证明 H1–H4；独立 Gate 无充分证据时仍保留父版。

历史证据归属：根目录 `CODE_COMPLETE_REPORT.md` 的原始 79 测试/22 对照和旧证据包对应 `3ccda3f`，
需在该版本回放。本次新增证据按新实现哈希单独保存，不改写旧日志或伪装为同一实现的重放。
